# Roadmap

This roadmap describes review goals, not release promises. Dates will be added only when a maintainer has capacity and the required review is available.

## 0.1 — Clean OSS baseline

- [x] Create a clean-history public export with project license and contribution guidance.
- [x] Keep private operating records and real participant/contact data out of the public tree.
- [x] Verify install, tests, and a web export from a clean checkout.
- [ ] Review the initial export and merge its public baseline PR.

## 0.2 — PWA and contributor-ready

- [x] Connect public UX and feature intake to a privacy-aware in-app entry point.
- [x] Prepare Vercel web export and preview configuration.
- [ ] Connect an owned Vercel project and make the production release decision.
- [ ] Add a PWA manifest, rights-cleared icons, and accessible installation behavior.
- [ ] Add a versioned service worker with explicit update and offline-cache rules.
- [ ] Verify browser storage, notification support, and offline recovery on supported browsers.
- [x] Enable Discussions and publish the starter labels and first bounded issues.
- [ ] Document accessibility expectations and a repeatable demo path.
- [ ] Publish a maintainer-reviewed architecture map.

## 0.3 — Reviewed learning content

- [ ] Review user-facing behavior and animal-care content with qualified professionals.
- [ ] Record sources, limitations, and review scope for every promoted learning card.
- [ ] Keep unreviewed research and runtime content in separate states.

## 1.0 — Release candidate

- [ ] Complete privacy, safety, accessibility, dependency-license, and platform reviews.
- [ ] Demonstrate clean installation and supported-platform builds from a tagged commit.
- [ ] Publish release notes that describe known limits and the exact public commit.

## Milestone policy

Maintainers create a GitHub milestone only when scope and acceptance checks are concrete. **0.1 Clean OSS baseline** covers the initial export review; [0.2 Public PWA alpha](https://github.com/e3o-labs/pet-readiness-simulator/milestone/2) covers public feedback, contributor setup, and verified PWA behavior. A milestone does not promise a date. Health/behavior content and new data collection remain gated on the required reviewers.
