# 사용자 의견과 기여 운영

## 체험 → 의견 → 작은 작업

서비스의 **의견 보내기**에서 [사용 경험](https://github.com/e3o-labs/pet-readiness-simulator/issues/2)과 [기능 제안](https://github.com/e3o-labs/pet-readiness-simulator/issues/3)을 남길 수 있습니다. GitHub 계정이 필요하며 모든 글과 댓글은 공개됩니다. 초기 접수 게시글은 기본 브랜치에 양식이 반영되기 전에도 사용할 수 있습니다. 양식이 반영되면 개별 UX feedback, Bug report, Feature proposal을 우선 사용합니다.

기기에 저장된 생활 조건·회고·진행 기록을 GitHub에 자동 첨부하지 않습니다. 사용자에게 실제 돌봄 기록, 연락처, 개인 사정이나 건강 정보를 요청하지 않습니다. 예시와 재현 자료는 가상으로 작성합니다. 보안 취약점은 [비공개 신고 안내](../SECURITY.md)를 따릅니다.

GitHub 계정 없이 의견을 접수하는 기능은 아직 없습니다. 추가하려면 공개 개인정보 안내, 최소 수집 항목, 보관·삭제 정책과 접수 운영자를 먼저 정하고 maintainer 검토를 받아야 합니다.

## 관리자가 처리하는 순서

1. 새 이슈에 `needs-triage`를 붙이고 문제·현재 방법·사용자 영향·재현 단계가 충분한지 확인합니다. 접수 게시글의 댓글은 관리자가 개별 이슈로 옮기고 원문에 링크를 남깁니다.
2. 같은 문제는 기존 이슈에 연결합니다. 채택하거나 보류하는 이유를 공개 댓글로 남깁니다. 실제 인원 수나 효과를 추정해서 쓰지 않습니다.
3. 동작 변경은 Discussion 또는 이슈의 짧은 명세로 **문제, 최소 범위, 제외 범위, 확인 기준, 필요한 검토**를 합의합니다.
4. 작업이 가능해지면 `planned`와 milestone을 지정하고, 기여자가 범위를 확인하면 `in-progress`를 붙입니다. 합의되지 않은 제안을 구현 약속으로 취급하지 않습니다.
5. PR에 원래 의견·명세를 연결하고 확인 결과를 적습니다. maintainer가 검토·병합한 뒤 원래 의견에 결과와 공개 SHA를 연결합니다.

관리자에게 고정 응답 시간이나 개발 일정을 보장하지 않습니다. 운영 여건에 맞춰 미검토 의견과 milestone을 확인하고, 우선순위가 바뀌면 이유를 남깁니다.

## 우선순위

| 순서 | 판단 기준 | 처리 |
| --- | --- | --- |
| 먼저 | 기록 손실, 개인정보 노출, 위험한 오해, 핵심 흐름을 막는 접근성 문제 | maintainer 확인 후 필요하면 배포 중단·수정 |
| 다음 | 시작·돌봄 연습·기록·리포트를 완료하기 어려움 | 재현 가능한 가장 작은 개선으로 범위 확정 |
| 이후 | 반복되는 불편, 설치·오프라인·업데이트 문제 | 영향과 작업 크기를 비교해 0.2 milestone 후보로 지정 |
| 연구 | 새로운 추천·점수·건강/행동 설명, 추가 데이터 수집 | 검토자가 확보될 때까지 연구/명세 상태 유지 |

## 라벨과 참여 수준

| 라벨 | 의미 |
| --- | --- |
| `feedback` / `ux` | 체험 의견 접수 / 사용 흐름·문구·접근성 |
| `needs-triage` | 범위와 검토 필요성을 확인 중 |
| `planned` / `in-progress` | 합의된 작업 / 담당 기여자가 진행 중 |
| `good first issue` | 작은 범위, 명확한 확인 기준, 시작할 위치가 있는 첫 기여 |
| `help wanted` | 명세가 있는 기여 요청. 작업 전에 댓글로 범위를 확인 |
| `pwa` | 설치·오프라인·업데이트·브라우저 지원 |
| `research` / `safety-review` | 출처 검토 / maintainer gate가 필요한 변경 |

문서 → UX → 테스트 → 코드 → 연구는 난이도 순위가 아니라 참여 분야입니다. 각 분야의 시작 방법과 검토 조건은 [CONTRIBUTING](../CONTRIBUTING.md)에 있습니다. 안전·개인정보·의학/행동 정보·점수 변경은 maintainer 확인과 필요할 때 자격 있는 전문가의 검토를 거칩니다. 접수나 라벨만으로 사용자에게 노출할 내용이 승인되지는 않습니다.

## 공개 목표와 운영 연결

[0.2 Public PWA alpha](https://github.com/e3o-labs/pet-readiness-simulator/milestone/2)의 목표는 링크 체험, 공개 의견 접수, 첫 기여, 설치·오프라인·업데이트 검증입니다. 체험용 웹 배포와 설치형 PWA 완료는 별도 단계로 표시합니다. [ROADMAP](../ROADMAP.md)과 이슈의 확인 기준을 함께 관리합니다.

Public 저장소가 제품 코드의 기준입니다. Private 운영 저장소에는 공개 commit SHA, tag(있을 때), 배포 주소/ID, 환경, 검증 결과를 연결합니다. 실제 사용자 자료와 운영 증거를 공개 이슈에 복사하지 않습니다. 배포와 되돌리기는 [deployment 문서](deployment.md)를 따릅니다.
